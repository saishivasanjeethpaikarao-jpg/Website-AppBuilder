Your AI key and publish tokens live in Settings, kept in this browser and used only when you generate or publish. On Replit, Secrets are encrypted at rest and injected as environment variables. Replit docs ↗

In the builderTask board

Every project's work sits on a board in the workspace — Draft → Active → Ready → Done. Approved plans land here as tasks; stage one as Ready, hit Apply, and the builder saves a History checkpoint first, then makes the change.

In the builderProject brief & always-on instructions

Each project has a Brief tab — what it is, who it's for, the rules — and the generator reads it before every build or edit. Your account-wide always-on instructions in Settings are prepended to every prompt on top of that.

In the builderLayout controls

The visual inspector now steers real layout — a 3×3 alignment picker, row/column direction, gap, and padding & margin per side — written straight into the element's CSS in the preview.

In the builderMulti-piece projects

One project can hold a website plus HTML slide decks (present them full-screen, or export a standalone file) plus data views that chart numbers you paste in — switch pieces above the preview.

In the builderProject data & uploads

The Data tab keeps simple tables you create and edit row by row, plus file uploads that go to your Supabase project's project-assets bucket while you're signed in — all saved with the project.

In the builderSEO helper

Audits your site's title, description, headings, image alt text and social preview tags, scores them, and fixes what it can in one click. Publishes include a generated sitemap.xml and robots.txt.

In the builderSelf-check

Every preview refresh re-runs checks inside the preview itself — console errors, broken links and images, missing alt text and page weight — and lists the results under the preview.

In the builderFeedback inbox

A small widget snippet for your published site posts visitor feedback to your project's Supabase feedback store; the Inbox tab lists it, with a one-tap “send to generator” for acting on it.

Replit referenceGit & GitHub

Replit referenceMobile apps

Replit referenceLive-app agents

On Replit, Monitoring, Performance and SEO agents watch a published app and fix issues after launch. Nothing monitors your site from here once you've published. Replit docs ↗

Replit referenceIntegrations & MCP

On Replit, 100+ connectors (Stripe, OpenAI, Shopify…) activate from a prompt, plus MCP servers in and out. This builder's equivalent is the Plugins tab, above. Replit docs ↗

Replit referenceTeams & multiplayer

On Replit, teams co-build in real time with cursor presence, a shared task board and per-person Agent threads. This builder is single-user, in your own browser. Replit docs ↗

Task board

The work for this project, in four columns. Approved plans land here as tasks; add your own by hand. Move a task to Ready, then hit Apply — the builder saves a History checkpoint first, then makes the change. Tasks save with the project and sync with it, like the files.

The context the generator reads before every build and edit of this project — what it is, who it's for, the look, and the hard rules. It sits on top of your account's always-on instructions from Settings.

Skills library

Pro design skill packs, built in. Switched-on packs do two jobs: their rules are injected into the generator's instructions, and their guidance sits here while you edit.

Add a skill

Enabled custom skills work exactly like built-in packs: their rules go into the generator's instructions, and the design audit checks for the measurable ones it can (font sizes, contrast, spacing keywords are read as guidance).

Checks the live preview against the switched-on packs — contrast, font sizes, spacing, touch targets and mobile layout — and lists what to fix.

Tools & Plugins

Connect external tools and use them while you build — insert a stock photo, an icon or a font, wire a form, a backend, analytics or payments. Keys are stored only in this browser, and connected plugins are baked into the project, so they stay live when you publish.

Publish your site

Deploy the current project straight from here. Add your own platform tokens once in Settings — they're stored only in this browser (localStorage), and are sent only to the platform you publish to.

⚙ Settings — API tokens

Tokens never leave this browser except in the publish request to that platform's own API.

Render note: Render hosts sites from a Git repository, not file uploads — publish to GitHub first, paste that repo URL in the Render card, and Render will build from it.

Project pieces

One project can hold more than a website. Add a slide deck or a data view next to your site — they share the project's name, brief, data and history, and each one opens in the preview when you tap it above the preview or in the list below.

Data & uploads

Tables and files for this project's app. They are saved with the project — in the same project storage as your site's files — and sync with your account, exactly like the files do. A published static site doesn't read them on its own; use Insert into page to bake a table into the site, or download the data and wire it up in code.

Files for this project. Signed in, uploads go to your Supabase project's project-assets storage bucket and the site can link to them from anywhere. If the bucket can't be reached, the file is kept inside the project instead and labelled as such.

SEO helper

A plain-English audit of your site's HTML — the title and description search engines show, your headings, image alt text and the tags social apps use for previews. Every fix below edits the real code in index.html.

sitemap.xml and robots.txt are generated from your project name and added automatically to every ZIP download and platform publish, addressed to your builder.site address. If you publish under your own domain instead, update the two addresses inside them after deploying.

Feedback inbox

Real messages from people using your site. Add the feedback widget to your site — visitors get a small Feedback button, and what they send lands here. Signed in, messages are stored in your Supabase project's feedback table; submissions you make from this builder's own preview are kept with the project and labelled as preview tests.
